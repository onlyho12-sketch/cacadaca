# 07. 구현 및 인수인계

## 1. 담당자에게 전달할 핵심 요청

```text
실제 실험이나 실제 Gloss Meter 보정은 수행하지 않습니다.
확보된 논문값과 PolyTwin 설계식을 이용하여 Isaac Lab 내부에 폴리싱 물리·품질
디지털 트윈을 코드로 구현합니다.

Isaac Lab은 로봇·패드·접촉을 계산하고, 커스텀 LiteraturePolishingModel은 위치별
Removal/Height/Scratch/Ra/Rz/Clearcoat 상태를 갱신합니다. LiteratureGlossProxyModel은
논문의 20° GU 앵커를 이용해 simulation GU proxy를 계산합니다.

PPO는 다양한 평면·볼록면·오목면·자유곡면에서 기준 제어기에 잔차를 더해
접촉·경로·품질을 개선합니다. BO는 디지털 트윈 안에서 Force/RPM/Feed/Step-over
레시피를 탐색합니다.
```

## 2. 구현 순서

### Step 1. 기준 config와 schema

- 논문 파라미터 manifest
- SurfaceState schema
- ProcessRecipe schema
- GlossSample schema
- observation/action/reward schema
- Train/Validation/Test surface manifest

### Step 2. 표면상태 모델

- 20×20 cm 평면 grid
- correlated normal roughness
- random Scratch generator
- pad footprint
- pressure/relative-speed/removal식
- Height/Scratch/Clearcoat update
- Ra/Rz 계산
- reference 평균 제거량 3 μm 정규화

### Step 3. GU proxy

- 25/78/89 GU anchor
- Ra/Scratch/Uniformity/Clearcoat/Optical 품질항
- 70 GU 목표
- current before/after relative gloss 회귀시험
- Before/After GU heatmap

### Step 4. Isaac Lab 연결

- v5 baseline controller adapter
- residual action=0 비교
- physics/contact aggregation
- PolishingModel.step 호출
- reward와 termination
- raw step logger

### Step 5. 곡면 일반화

- plane/cylinder/sphere/saddle/freeform/transition generator
- local normal/tangent/k1/k2
- map crop observation
- curriculum
- split manifest

### Step 6. PPO

- zero-mean residual actor 초기화
- parallel rollout
- fixed validation 평가
- best checkpoint 선택
- reward hacking/ablation

### Step 7. BO

- recipe search space
- digital-twin evaluator
- constrained objective
- BO surrogate/acquisition
- best feasible recipe JSON
- PPO context 연결

### Step 8. 곡면 Local 20° RTX

- local frame
- source/camera ±20°
- curvature footprint 검사
- Path Tracing measurement
- surface GU map

### Step 9. 최종 통합

- 새 자동차 또는 물체 mesh
- path planner
- BO recipe
- PPO policy
- surface quality state
- RTX visualization
- final evaluation summary

## 7. 구현 시 금지

- 기존 MD를 읽고 실제 실험 데이터를 기다리도록 작업을 중단하지 않는다.
- GU calibration 장비가 없다는 이유로 GU proxy 구현을 생략하지 않는다.
- 논문값과 PT-DESIGN 연결계수를 구분 없이 hard-code하지 않는다.
- Lux를 GU로 바꾸는 임의 단위변환을 하지 않는다.
- 품질맵 없이 최종 scalar GU 하나만 업데이트하지 않는다.
- 정상부를 과도하게 제거하는 정책에 높은 보상을 주지 않는다.
- 하나의 자동차 mesh 결과만으로 일반화 완료라고 하지 않는다.
