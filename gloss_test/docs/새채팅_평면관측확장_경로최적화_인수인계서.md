## 1. 최종 목표

최종 목표는 단순히 모든 합성 표면을 억지로 통과시키는 것이 아니다.

1. 3D 스캔과 결함 지도로 안전한 기본 폴리싱 경로를 만든다.
2. IK·충돌·도달 가능성 검사를 통과한 경로에서 로봇을 움직인다.
3. 하위 PPO가 순간 접촉력과 이송속도를 숙련공처럼 조절한다.
4. pass 종료 검사 결과를 보고 상위 공정 제어기가 다음 pass의 RPM, step-over, 경로 방향,
   가장자리 보정, 기본 힘·속도 및 중단 여부를 정한다.
5. GU, Ra, Rz, scratch, clearcoat, 힘, 온도를 동시에 만족하면 성공으로 판정한다.
6. 안전하게 더 개선할 수 없는 구역은 무한 반복하지 않고 현재 공정의 한계와 다음 조치
   (다른 pad/compound, 국부 샌딩, clearcoat 보수·재도장 등)를 사용자에게 알린다.
7. 평면이 안정된 뒤 같은 구조를 보디 라인·곡면으로 확장한다.

즉 숙련공 기술 저장의 대상은 `성공 동작`뿐 아니라 `마무리 전환`, `안전 중단`,
`공정 변경 판단`까지다.

## 4. 현재 평면과 경로의 기하학적 문제

### 4.1 현재 수치

- 품질 patch: `120×120 mm`
- 품질 격자: `2 mm`, 즉 60×60 = 3,600점
- 패드 직경/반경: `110/55 mm`
- step-over ratio: `0.184`
- 레스터 간격: `20.24 mm`
- 레스터 line: 6개
- line y: 약 10.12, 30.36, 50.60, 70.84, 91.08, 111.32 mm
- x 중심 경로: 0→120 mm 또는 120→0 mm
- 첫 점: 왼쪽 아래 경계 부근 `(0, 10.12 mm)`

현재도 패드 전체가 품질 patch 안에 있지 않다. x 끝점에서는 패드 절반이 품질영역 밖으로
나간다. 이것 자체는 평가 셀이 실제 패널 끝이 아니라면 자연스럽다.

문제는 현재 PhysX Workpiece가 `160×160 mm`, 즉 품질 patch보다 사방 20 mm만 크다는 점이다.
패드는 품질 경계에서 반경 55 mm까지 뻗으므로 일부가 실제 Workpiece 밖에도 걸친다.
품질 모델은 patch 밖 footprint를 잘라 계산하므로 연속 차체의 접촉과 완전히 일치하지 않는다.

### 4.2 사용자와 최종 합의한 경계 원칙

`패드 전체를 품질 셀 내부에 제한`하지 않는다. 원형 패드를 사각 셀 내부에만 두면 꼭짓점이
가공되지 않으며 지금까지의 경로와도 달라진다.

대신 다음 두 경계를 분리한다.

1. **평가 셀 경계**: 가상의 검사 경계. 패드가 넘어가도 된다.
2. **실제 패널 끝·틈·단차**: 물리적 경계. 별도 edge 안전규칙과 필요 시 작은 패드가 필요하다.

평면 내부 셀 실험에서는 더 큰 연속 물리 평판과 전체 품질 상태맵을 만들고, 가운데 ROI의
품질을 판정한다. 패드가 ROI 밖으로 나가도 전체 패드는 연속된 물리 차체 위에 있어야 한다.

초기 검토 후보:

- 전체 물리/품질 상태맵: `300×300 mm`
- 중앙 판정 ROI: `200×200 mm`
- 상태맵 전체의 scratch/removal/clearcoat를 계산
- ROI만 최종 품질 집계

이 수치는 확정 상수가 아니라 첫 geometry/coverage test 후보이며, 구현 전 메모리·시간과
패드 coverage를 계산해 확정한다.

### 4.3 현재 경로의 예비 coverage 계산

정책 action과 scratch 선택 제거를 제외하고 현 레스터와 제거 footprint만 계산한 예비 결과:

| 위치 | 평균 대비 상대 제거 노출량(현재 제거식 압력 보정 포함) |
|---|---:|
| 중앙 40×40 mm | 약 1.15 |
| 좌우 가장자리 | 약 0.87 |
| 아래/위 가장자리 | 약 0.85/0.89 |
| 네 모서리 | 약 0.73~0.77 |

중앙이 모서리보다 약 50~58% 큰 노출량을 받을 수 있다. 이는 원인 후보를 지지하지만 정식
PhysX/quality paired 결과는 아니다. 다음 단계에서 실제 `cumulative_removal_um`과 타일별
미세 Ra/waviness로 재검증한다.

단순히 시작점을 모서리로 바꾸는 것은 해결책이 아니다. 현재 경로도 왼쪽 아래 경계
부근에서 시작하며, 같은 line 집합을 순서만 바꾸면 최종 누적 coverage는 거의 같다.

## 5. Scratch 범위에 관한 확정 캐비어트

현재 우리와 비교 Git 모두 다음 생성기를 쓴다.

- scratch depth: `0.05~2.0 μm` 균일분포
- 개수: 4~12
- 폭: 2 mm (`PT-DESIGN`)
- 길이: 30~120 mm (`PT-DESIGN`)

문헌의 `0.05~2.0 μm`는 세차 브러시로 손상된 clearcoat 표본에서 관찰한 마·미세 scratch의
포괄 범위이며, 신차 실제 발생 분포가 아니다. 개별 미세 scratch가 밀집하면 swirl 외관으로
보일 수 있지만, 범위 전체를 `신차 swirl 분포`라고 부르면 안 된다.

`0.05~0.50 μm`는 경미한 swirl/mar 실험군 후보로 합리적이지만, 기존 범위를 단순 교체하면
균일분포 평균 깊이가 1.025→0.275 μm로 약 73% 감소해 시험 자체가 크게 쉬워진다.

따라서 후속 원칙:

- 경미군 `0.05~0.50 μm`
- 중간/깊은 교정군 `0.50~2.0 μm`
- 혼합비는 실측이 없으므로 `PT-DESIGN`
- 난이도군별 통과율을 별도 보고
- 기존 결과와 직접 비교할 때 분포 변경 caveat 명시

Scratch 범위 변경만으로 Ra 모델의 미세거칠기/경로 waviness 혼합 문제는 해결되지 않는다.

## 6. 다음 PPO에 필요한 정보와 표현 방식

사용자가 요구한 정보:

1. 현재 pass 번호
2. 현재 전체 GU
3. 현재 Ra·Rz
4. clearcoat 남은 예산
5. 2차원 scratch 지도
6. 2차원 누적 제거량 지도
7. 중앙·가장자리 제거량 차이
8. 아직 덜 닦인 타일 위치
9. 이미 과도하게 닦인 타일 위치

### 6.1 전역 scalar 관측 후보

- normalized `pass_idx`
- 직전 검사 `GU_target - GU`
- 직전 검사 `Ra - Ra_target`
- 직전 검사 `Rz - Rz_target`
- 전역 최소 clearcoat 안전여유
- 전역 누적 제거량 평균
- 제거량 균일도(CV 또는 max-min)
- 중앙 평균 제거량 − 가장자리 평균 제거량
- 공정 stage: correction/finishing

`현재 pass 번호`와 `재폴리싱 횟수`는 거의 중복이므로 normalized pass 하나부터 쓴다.
공정 stage는 상태기계가 정의한 값일 때만 명시적으로 넣는다.

### 6.2 공간 관측

전체 고해상도 지도는 환경 상태와 CSV에 보존한다. PPO MLP에는 우선 기존 타일 체계와 맞춘
5×5 축약 지도를 넣는다.

- scratch 5×5
- cumulative removal 5×5
- under-polished mask 5×5
- over-polished mask 5×5

8·9번은 별도 물리장이 아니라 scratch/removal/target/clearcoat에서 파생한 mask다.
중앙/edge 이진 플래그보다 경계까지 정규화 거리, planned coverage, 실제 dwell/removal을
사용하는 편이 낫다.

### 6.3 실기 적용 가능성

시뮬레이션에서 매 0.05초 전체 GU/Ra/Rz를 다시 계산해 PPO에 주면 실제 로봇에 없는 oracle이
될 수 있다. 전역 GU/Ra/Rz는 pass 종료 검사에서 갱신하고 다음 pass 동안 고정한다. 작업 중에는
접촉력, 국소 scratch/removal, clearcoat model estimate, 온도 등을 갱신한다.

### 6.4 먼저 할 ablation

관측을 한꺼번에 확장한 모델 하나만 학습하지 않는다.

1. 기존 14ch baseline
2. 기존 14ch + pass/전역 품질 scalar
3. 위 scalar + 5×5 공간지도

같은 짧은 학습·같은 seed로 비교해 가장 나은 구성을 본 학습한다. 비교 Git의 단순 4채널
lookahead 실험은 99→95/150로 악화됐으므로 `공간정보를 넣으면 무조건 좋아진다`고 가정하지 않는다.

```text
Action
├─ ΔForce
└─ ΔFeed
```

- ΔForce: base force의 ±30%
- ΔFeed: base feed의 ±50%
- 현재 12.7 mm/s 기준 실제 feed 6.35~19.05 mm/s

관측 확장만으로 pass-aware finishing이 가능한지 먼저 검증한다.

### 7.2 바로 PPO 행동으로 넣지 않을 항목

- RPM: 모터 관성·열 때문에 pass/line 단위 상위 변수로 시작
- step-over: 다음 line 위치를 정하므로 line/pass 단위 상위 변수
- 자유 `Δx, Δy, Δz`: 행동공간·안전 위험이 크므로 보류
- 법선 위치와 force를 동시에 자유 행동으로 주면 두 제어가 충돌할 수 있음

### 7.3 최종 계층 구조

```text
3D Scan / 결함 지도
        ↓
안전한 기본 경로 생성
        ↓
IK / Collision / Reachability
        ↓
상위 공정 제어기 (pass 또는 line 단위)
 ├─ RPM
 ├─ Step-over
 ├─ 경로 방향
 ├─ Edge 보정
 ├─ Base force/feed
 └─ Stop/Continue
        ↓
하위 PPO (20 Hz)
 ├─ ΔForce
 └─ ΔFeed
        ↓
PhysX 폴리싱 → 검사 → 다음 pass
```

기존 BO는 고정 recipe 탐색기다. 바로 온라인 상위 제어기가 되는 것은 아니다. 상태별 offline
BO/contextual BO/대리모델로 pass recipe library를 만들고, 처음에는 명시적 상태기계가 그중
하나를 고르는 방법이 시간과 안전 면에서 유리하다.

경로 residual RL은 마지막 단계에서 작은 접선 방향 오프셋, line 종료 시 다음 step-over 선택
정도로 제한해 도입한다. 기준 경로는 항상 유지하고 안전 projection을 통과시킨다.

## 8. Step-over와 경로 실험 계획

현재 step-over `0.184`는 과거 약 5.95 mm/s 해석식 BO 조건에서 나온 값이다. 현재의
12.7 mm/s·PhysX·반복 폴리싱 조건에서 재최적화되지 않았다.

|---:|---:|---:|
| 0.18 | 19.8 mm | 82% |
| 0.25 | 27.5 mm | 75% |
| 0.32 | 35.2 mm | 68% |
| 0.40 | 44.0 mm | 60% |

경로 후보:

- 1차 가로 raster → 2차 같은 방향
- 1차 가로 → 2차 세로 cross-raster
- edge correction line 포함/미포함
- 필요 시 pass별 line 순서 변경(열 순서 효과 확인용)

모든 후보는 같은 seed로 먼저 비학습/고정정책 16표면 paired screen을 한다. 평가항목:

- GU, 미세 Ra/Rz, scratch

상위 1~2개만 100표면 평가 또는 새 BC/PPO에 사용한다.

## 9. 새 BC/PPO 계획

관측 차원이 바뀌면 기존 checkpoint를 그대로 새 네트워크에 load할 수 없다.

1. 기존 챔피언은 보존하고 teacher action 생성에 사용한다.
2. 새 관측을 기록하는 BC dataset을 별도 경로로 수집한다.
3. pass 1 teacher는 현 챔피언 행동을 이용할 수 있다.
4. pass 2+ teacher에는 선정된 finishing recipe/상태기계 행동을 포함한다.
5. 모방 MSE, 센서 fault, 접촉률, pass/stage 분포를 보고한다.
6. 짧은 observation ablation 뒤 최종 구성만 100~200환경 PPO로 본 학습한다.
7. checkpoint는 iteration별 보존하고 8→16→100 같은 seed로 선택한다.

본 평가 기준은 평균 reward가 아니라 다음 우선순위다.

1. 전체 동시통과 수
2. 힘·clearcoat·온도 안전
3. Ra 회귀 감소
4. 제거량 균일도
5. GU 및 scratch 개선
6. 공정시간

2,942 step보다 짧으므로 **Gate E4의 terminal event는 구조적으로 0**이다. 따라서

보상 배선과 안전 업데이트만 검증한 실험으로 해석한다.

현재 48-step rollout에서 첫 terminal은 62번째, 12환경 전부의 첫 terminal은 75번째
iteration까지 가야 나타난다. 더 중요하게, terminal이 들어온 rollout 안에서도
rollout 시작부터 종료까지의 step만 직접 GAE credit을 받는다. 정확한 구간
최소/평균/최대는 6/21/40 step으로 전체 경로의 평균 0.647%에 불과하다.

- 현 `gamma=0.9995`, `lambda=0.95`에서 terminal→해당 rollout 시작 GAE weight
  최소/평균/최대는 0.132663/0.418397/0.771848이다.
- terminal reward 최소/평균/최대는 654.469727/691.073919/715.381348이고,
  `terminal / episode |dense|` 비율은 평균 3.214다. 크기가 작은 것이 아니라 시간 경계가
  주요 문제다.
- 중단없는 하나의 3,269-step trajectory라면 gamma 0.9995의 시작 weight는 평균
  0.196218이지만, PPO storage가 48 step마다 update로 끊기므로 이 가정은 실제로
  구현되지 않는다. gamma만 높여서는 해결되지 않는다.
- 단순히 rollout을 512로 늘리면 direct span은 늘지만 lambda 0.95 감쇠로 rollout
  시작 weight가 평균 0.000040으로 줄어든다. rollout 길이만 큰 값으로 바꾸는 것도

현 측정 episode 정렬에서 direct span 평균 79.67 step, rollout 시작 weight 평균 0.472701이다.
단, lambda 증가는 분산을 키울 수 있으므로 같은 seed/checkpoint/안전 gate로 비교해야 하며 자동
