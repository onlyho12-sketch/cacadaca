RL(잔차 PPO) 담당자에게 전달하는 최소 패키지. **이 폴더만 복사하면 된다.**

```

```

> ⚠ `bc_mlp.pt` 단독으로는 열 수 없다. 모델 클래스 정의가 필요하므로 `bc_policy.py`를 반드시 함께 쓸 것.

전체 설계 배경은 `learning/PLAN_BC_V2.md`(특히 7장)와 `learning/HANDOFF.md` 참고.

```python
from bc_policy import BCPolicy
```

## 2. 입출력

### 입력 9개 — 순서 고정

| # | 이름 | 의미 | 범위 |
|---|---|---|---|
| 0–2 | `normal_x/y/z` | 표면 법선 (단위벡터) | `normal_z ≥ 0` |
| 3 | `tilt_deg` | `acos(normal_z)` | 0–90 |
| 4 | `curvature` | 점군 국소 PCA `λ_min/Σλ` | 평면 ≈ 0 |
| 5 | `progress` | 구간 내 경로 진행률 | 0–1 |
| 6 | `is_side` | 측면=1 / 상면=0 | **로봇 1대 환경에서는 `tilt_deg > 45`로 대체** |
| 7 | `phase` | 연마 단계 | **0 고정** (예약 슬롯) |
| 8 | `prev_force` | 직전 스텝 실측 접촉력 [N] | 0.27–6.92 |

### 출력 2개

| 이름 | 단위 | 용도 |
|---|---|---|
| `contact_force_n` | N | **힘 제어기의 목표힘 setpoint 자리에 투입** (아래 배포 계약) |
| `feed_speed_mps` | m/s | 경로 추종 속도 |

회전속도는 고정(`3000 rpm`)이라 출력에 없다.

---

## 3. ★ 배포 계약 — 출력을 어디에 꽂는가

**`contact_force_n`을 어드미턴스/힘 제어기의 목표힘 자리에 넣는다.**

값의 출처는 "시연에서 **실제로 달성된** 힘"이지 "규칙이 **명령한** 힘"이 아니다. 이유:

```
규칙 명령 평균 5.82 N  vs  실측 평균 3.12 N   (98%의 스텝에서 명령 > 실제)
시연의 65.7%가 압입 깊이 한계에 포화된 채로도 평균 3.59 N밖에 못 냈다
```

규칙의 목표힘은 **물리적으로 도달 불가능한 값**이었다. 그것을 복제하면 제어기가 계속 깊이 한계에
붙어 있게 되고, **잔차 RL이 Δ를 줘도 한쪽 방향으로는 아무 효과가 없다.** 실측힘을 목표로 주면
포화되지 않는 지점에 안착해 양방향 보정 여유가 생긴다.

**검증 숙제:** BC 목표힘 투입 시 압입 포화율이 65.7%(시연치)보다 확실히 낮아지는지 확인할 것.

---

## 4. ★ 착수 전 필수 — 전이 가능한지 먼저 확인

**RL을 며칠 돌린 뒤에 "BC가 쓸모없었다"를 알면 낭비다.** 학습 시작 전에 30분이면 끝난다.

```python
# 새 환경에서 규칙 컨트롤러로 몇 구간 주행 → 접촉력 수집
forces = collect_forces_from_rule_controller()

report = policy.check_transfer(forces)
print(report["verdict"])
```

판정 기준: 평균 접촉력 배율이 0.4–2.5배 안에 들고, 관측의 절반 이상이 학습 범위(0.27–6.92 N)에 들어야 한다.

**불일치가 나오면** — 이 체크포인트는 버리고 **새 환경 로그로 BC를 재학습**한다.
파이프라인(`extract_dataset.py` → `train.py` → `evaluate.py`)은 그대로 재사용 가능하고 반나절이면 된다.
우리가 만든 자산은 특정 가중치가 아니라 방법론과 도구다.

### 왜 불일치가 날 수 있나

우리 시뮬은 **가상 스프링** 접촉 모델이다 (강체 충돌 OFF, 패드 침투 깊이로 힘 계산).
Isaac Lab에서 강체 접촉을 쓰면 완전히 다른 스케일(예: 50 N)이 나오고,
BC는 그런 입력을 본 적이 없어 무의미한 값을 뱉는다.

### 함께 확인할 것

- `curvature` 계산 방식 일치 — 우리는 점군 KDTree PCA(`λ_min/Σλ`). 메시 기반이면 값이 달라진다.
- **병렬화**: KDTree 쿼리를 2048 env × 매 스텝 돌릴 수 없다. 법선·곡률은 **사전 계산해 텐서로 보유**할 것.

## 5. 잔차 RL에서의 사용 형태

BC는 **동결**이다 (`bc_policy.py`가 로드 시 `requires_grad_(False)` 처리).

```python
a_base = policy.predict(obs_9)                  # BC: 이 표면의 표준 동작
delta  = residual_net(obs_9, remaining_removal) # 잔차: 목표 달성을 위한 보정
action = clip(a_base + delta, bounds)
```

**BC는 잔여량을 보지 않고, 잔차만 본다.** 그래서 목표 두께가 바뀌어도 BC 재학습이 필요 없다.

| 항목 | 값 | 근거 |
|---|---|---|
| 잔차 bound (힘) | ±2.0 N | 실측 − 스무딩 변동의 95% = ±1.75 N |
| 잔차 bound (속도) | ±270 mm/s | 고속/크리프 이중모드 반영 — 과대 가능, 튜닝 대상 |
| BC 출력 범위 | 0.27–6.92 N / 0–793 mm/s | 데이터셋 통계 (평균 3.12 N / 131 mm/s) |
| 에피소드 | 1구간 = 중앙값 28스텝 (4–184) | 로그 실측 |

## 7. 알아둘 한계

1. **`normal_x/y`는 월드 축 기준**이라 오브젝트를 회전시키면 값이 달라진다.
   `tilt`(= `normal_z`)만 회전 불변. 현재 importance가 거의 0(`normal_x`는 −0.010)이라 유지했으나,
   전이가 문제되면 6개 입력안(`tilt`, `curvature`, `normal_z`, `progress`, `is_side`, `prev_force`)으로
   축소 검토. 그 구성의 성능은 힘 0.311 N / 속도 48.2 mm/s였다.
2. **`phase`는 0 고정.** 죽은 입력이지만 다단계 공정 대비로 자리를 유지했다. 항상 0을 넣을 것.
3. **선생님은 숙련공이 아니다.** 규칙 컨트롤러 + 물리엔진이 만든 시연을 복제한 것이다.
   BC의 역할은 RL의 출발점 제공이고, 실력 개선은 잔차 RL 담당이다.
   대외 표현은 "숙련공 재현"이 아니라 **"규칙 기반 시연으로 부트스트랩된 정책"**.
