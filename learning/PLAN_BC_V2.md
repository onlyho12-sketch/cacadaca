## 6. Preston 재료 제거 모델 — RL 보상의 전제 (팀원 착수 대상)

### 6-1. 왜 필요한가

현 시뮬에는 **재료 제거·표면 조도 모델이 없다.** 추적하는 건 커버리지 카운트(점을 몇 개 칠했나)뿐이다.
(`grep -i "preston|removal|roughness|MRR" polishing_v5_modules/` → USD 렌더링 재질 속성만 나옴)

이 상태로 RL을 돌리면 보상에 넣을 게 "힘 추종 + 시간"뿐이고, **그건 규칙 컨트롤러가 이미 하는 일**이라
RL을 쓸 이유가 없다. 표면 품질을 최적화하려면 품질을 **측정할 수 있어야** 한다.

### 6-2. 식 — 고민할 것 없다 (Preston 1927, 유리 연마 표준)

```
Δh = k · P · v · dt
```
| 기호 | 의미 | 우리 값 (실측 데이터 기준) |
|---|---|---|
| `Δh` | 제거 깊이 | 임의 단위 |
| `k` | Preston 계수 | **1.0으로 두면 됨** (아래 6-3) |
| `P` | 접촉 압력 = 힘 / 패드면적 | 평균 **688 Pa** (범위 59~1526) |
| `v` | 패드-표면 상대속도 | **상수 ≈ 6~8 m/s** (아래 주의) |
| `dt` | 접촉 시간 | 스텝 dt = 1/60 s |

**주의 — `v`는 회전이 지배한다.**
```
회전 선속도 : 5.97 m/s (반경 중간) / 7.96 m/s (면적가중평균 2R/3)
이송 속도   : 평균 0.131 m/s
→ 회전이 이송보다 45~60배 빠름
```
회전속도는 이 프로젝트에서 **고정**(`PAD_SPIN_VELOCITY = 314.16 rad/s`)이므로 `v`는 상수다.
반경 중간이냐 면적가중이냐는 `k`에 흡수되므로 중요하지 않다. **하나 골라 고정하고 문서화만 하면 된다.**

따라서 실질적으로:
```
제거량 ∝ 힘 × 머무는 시간(dwell)          dwell ∝ 1 / 이송속도
```
**BC/RL의 출력 2개(힘, 이송속도)가 정확히 제거량을 결정한다** — 애초에 그래서 그 둘을 출력으로 골랐다.

### 6-3. `k`는 왜 아무 값이나 써도 되나

`k`는 원래 재료·연마재·슬러리별로 실험으로 재는 값이다. 하지만:

- **RL이 최적화할 목표는 "균일도"이고, 균일도는 스케일 불변이다.** `k`가 1이든 0.001이든
  "어디가 많이 갈리고 어디가 덜 갈렸나"의 비율은 동일하다.
- 따라서 `k = 1.0` (임의 단위)로 두고 시작하면 된다.

**⚠ 대신 정직하게 표현할 것:** `k`를 임의로 정하면 **"Ra 0.5µm 달성" 같은 절대 수치는 주장 불가**다.
"제거 균일도 N% 개선", "과연마 지점 M% 감소" 같은 **상대 개선**으로 표현해야 한다.
(설계 문서 2장의 과대주장 방지 원칙과 동일한 취지)

### 6-4. 구현 — `polish_viz`의 bool을 float로

이미 패드 반경 안의 점을 찾아 마킹하는 코드가 있다. **자료형만 바꾸면 된다.**

```python
# 현재 (visualization.py: PolishViz)
self._polished = np.zeros(len(points), dtype=bool)

def mark(self, pos):
    idx = self.kdtree.query_ball_point(pos, self.pad_radius)
    self._polished[idx] = True                  # 그냥 True

# 바꾼 뒤
self._removal = np.zeros(len(points), dtype=float)   # 누적 제거량

def mark(self, pos, force, dt):
    idx = self.kdtree.query_ball_point(pos, self.pad_radius)
    P = force / self.pad_area
    self._removal[idx] += K_PRESTON * P * V_SPIN * dt   # 누적
```

**정밀도를 올리고 싶으면 (선택):** 회전 패드는 바깥쪽이 더 빠르므로 `v(r) = ω·r`.
점별 반경 `r`을 구해 `removal += k · P · ω · r · dt`로 가중하면 실제 마모 패턴(가장자리가 더 갈림)에 가까워진다.

**⚠ 상수 불일치 주의:** 현재 `POLISH_MARK_RADIUS = 0.038`인데 실제 디스크는
`POLISHING_DISK_RADIUS = 0.055`다. 제거 모델을 붙일 땐 어느 쪽을 접촉 반경으로 볼지 정하고
면적 계산(`P = F/A`)과 일치시킬 것.

### 6-5. 보상 함수 설계

```
reward =
    - w1 · std(제거량)                  # 균일도 — 핵심 항
    - w2 · count(제거량 < 목표치)        # 덜 갈린 지점
    - w3 · count(제거량 > 상한)          # 과연마 (손상)
    - w4 · |Δa|                         # 잔차 페널티 (BC에서 과도 이탈 방지)
    - w5 · 에피소드 시간
```
w4가 없으면 잔차가 BC를 무시하고 커진다 — 잔차 RL의 의미가 사라지므로 필수.

### 6-6. 개선 여지 baseline — 규칙은 얼마나 불균일한가

현 로그(1737샘플)로 Preston 상대 제거량 `P · dwell`을 계산한 결과:
```
p5   117
중앙 828
p95 2714
→ p95/p5 = 23.2배
```
**같은 표면인데 어떤 지점은 다른 지점보다 23배 더 갈리고 있다.**
이것이 RL이 줄여야 할 목표이자, "규칙 대비 개선"을 주장할 정량 baseline이다.

### 6-7. 검증 방법 (설계 문서 7장 역추정과 연결)

Preston은 **다대일** 관계다 — (힘 5N, 느리게)와 (힘 10N, 빠르게)가 같은 제거량을 낸다.
따라서 "제거량이 목표에 맞았다"만으로는 과정이 타당했는지 알 수 없다. 설계 문서 7장대로:
1. 시뮬 데이터로 `(F, v) → 제거량` 회귀 모델 학습
2. 목표 제거량을 역산해 **물리적으로 타당한 (F, v) 범위** 도출
3. RL 정책이 낸 (F, v)가 그 범위 안인지 교차 확인

### 6-8. 착수 체크리스트

- [ ] 접촉 반경 확정 (`POLISH_MARK_RADIUS` 0.038 vs `POLISHING_DISK_RADIUS` 0.055) 및 면적 일치
- [ ] `PolishViz._polished` (bool) → `_removal` (float) 전환, `mark()`에 force·dt 인자 추가
- [ ] `K_PRESTON = 1.0`, `V_SPIN` 상수 확정 및 주석에 근거 기록
- [ ] 목표 제거량 / 과연마 상한 설정 (현 데이터의 중앙값 828을 기준선으로 삼는 것 권장)
- [ ] 균일도 지표(std 또는 p95/p5)를 매 에피소드 산출하도록 환경에 노출
- [ ] 규칙 컨트롤러 baseline 재측정 (p95/p5 = 23.2배가 새 환경에서도 유사한지)

## 7. RL 환경 설계 (2026-08-26 사용자와 합의)

> BC와의 근본 차이: **BC에는 목표가 없다.** 규칙이 7.49N을 명령해도 물리가 3.85N을 내면
> BC는 3.85를 배울 뿐, 그게 좋은 값인지 묻지 않는다. RL에서 처음으로 "목적"이 생긴다 —
> **사용자가 지정한 목표 두께만큼 깎기.**

### 7-1. 확정 사항

| 항목 | 결정 | 근거 |
|---|---|---|
| 경로 | **주어진다.** 에이전트는 힘·속도만 조절 | BC가 배운 형태와 동일. 경로까지 학습하면 BC 재사용 불가 |
| `is_side` | `tilt_deg > 45°`로 대체 | 로봇 1대 환경엔 측면/천장 구분이 없음. BC 재학습 불필요 |
| State | 기존 9개 + **잔여량** = 10개 | 아래 7-2 |
| 목표 맵 | **불균일**, 매 에피소드 **랜덤 생성** | 아래 7-3 |
| 패스 | 여러 번 허용, 최대 3회 | 1회 주행 시 50%가 목표 미달 (실측) |
| 시간 | 페널티가 아니라 **예산** | 아래 7-6 |
| 접촉 모델 | **보류** — 별도 결정 필요 | 7-8 |

### 7-2. State — 잔여량을 추가한다 (10개)

```
normal_x, normal_y, normal_z    # 표면 법선
tilt_deg                        # 기울기
curvature                       # 국소 곡률
progress                        # 경로 진행률
is_side                         # = (tilt_deg > 45°)  ← 대체 정의
phase                           # 0 고정 (예약)
prev_force                      # 직전 스텝 실측 접촉력 [N]
remaining_removal               # ★신규: 목표 − 현재 누적 제거량
```

**왜 "잔여량"인가 (현재 두께나 목표가 아니라):**
정책이 필요한 건 **차이**다. "500 깎였고 목표 800"이나 "0 깎였고 목표 300"이나 할 일은 같다.
잔여량만 주면 **목표 두께를 바꿔도 정책을 재학습할 필요가 없다** (goal-conditioned 정책).

**계산:** 패드 발자국(반경 R) 안 점들의 **평균 잔여량**. 실제로 깎이는 영역이 그곳이므로.

**BC와의 관계 — 재학습 불필요:**
```
[BC — 동결]   state 9개          → a_base    "이 표면의 표준 동작"
[잔차 — 학습]  state 9개 + 잔여량  → Δa       "여기 300 남았으니 +0.8N"
                                최종 = a_base + Δa
```
BC는 잔여량을 보지 않고, 잔차만 본다. 역할 분담이 깔끔해지고 BC 인터페이스가 그대로 유지된다.
잔차 RL이 원래 이런 구조를 위해 있는 것.

### 7-3. 목표 제거 맵 — 불균일 + 매 에피소드 랜덤

목표가 균일하면 정책이 "어디든 828 정도"로 외워서 넘어갈 수 있다. 불균일하면 불가능하다
(같은 기울기·곡률인데 옆자리는 목표가 다름) → **정책이 잔여량을 진짜로 읽게 된다.**

| 생성 방식 | 판정 |
|---|---|
| **① 랜덤 필드 (가우시안 블롭 몇 개)** | **채택.** 매 에피소드 재생성 |
| ② 기하 기반 (평면은 많이, 모서리는 적게) | **금지.** 아래 참고 |
| ③ 수동 지정 | 데모용만 |

**②를 금지하는 이유:** 목표가 곡률과 상관되면 정책이 잔여량 대신 곡률을 보고
"여긴 대충 이 정도겠지" 추측한다. 실제 목표가 달라지면 무너진다.
→ v1에서 `pos_z`를 목발로 삼아 좌표를 외웠던 것과 **정확히 같은 실패 패턴** (PLAN 0장 참고).

### 7-4. Action — 잔차 2개

```
Δ힘    ±2.0 N      (실측 − 스무딩 변동의 95% = ±1.75N 근거)
Δ속도  ±270 mm/s   (고속/크리프 이중모드 반영. 과대 가능 — 튜닝 대상)
최종 = clip(BC(state_9) + Δ),  tanh로 하드 클리핑
```

**RL이 실제로 배우는 것 — 두 개의 레버 트레이드오프:**
```
제거량 = k · P · v · dt
              ↑        ↑
         세게 누르기   천천히 가기(dwell↑)

잔여량 300을 채우려면:
  A) 힘 3.1 → 6.2N        제거량 2배, 시간 그대로   ← 공짜지만 손상 위험
  B) 속도 55 → 28mm/s     제거량 2배, 시간 2배      ← 안전하지만 느림
  C) 절충
```
급경사면 힘을 못 쓰고, 시간이 급하면 속도를 못 줄인다. **이 판단이 RL의 본체다.**
규칙 컨트롤러는 이 트레이드오프를 아예 하지 않는다.

### 7-5. Reward — 비대칭이 핵심

```
매 스텝:
    - w1 · (이번에 깎인 양 − 이번에 깎아야 할 양)²     # 조밀 보상
    - w2 · max(0, 초과분)²          ← 과연마      # w2 ≫ w3 (비대칭!)
    - w3 · max(0, 미달분)²          ← 미달
    - w4 · |Δa|                     # 잔차 페널티 (BC 이탈 억제, 필수)
에피소드 종료 시:
    - w6 · std(최종 잔여량)          # 균일도 보너스
```

**⚠ 비대칭이 필수인 이유 — 물리가 비대칭이다:**
```
덜 깎음  →  한 번 더 돌면 됨    (회복 가능)
더 깎음  →  되돌릴 수 없음       (영구 손상)
```
`w2 ≫ w3`가 아니면 정책이 **"일단 세게 깎고 보자"**를 배운다.

**조밀 보상을 쓰는 이유:** 균일도는 에피소드가 끝나야 알 수 있어 희소하다(28스텝 중 어느 행동이
잘못이었는지 알 수 없음 = 신용 할당 문제). 잔여량이 state에 있으므로 매 스텝
"얼마나 깎아야 하는지"가 명확하고, 매 지점에서 목표량을 맞추면 결과적으로 균일해진다.

### 7-6. Episode — 시간은 페널티가 아니라 예산

```
1 에피소드 = 한 구간을 목표 두께 도달까지 (여러 패스 허용)

종료:  · 전 지점 목표 도달        → 성공
       · 최대 패스 3회 초과       → 미달 종료
       · 스텝 예산 초과           → 시간 초과 + 감점
       · 힘 허용치 초과           → 즉시 종료 + 큰 감점 (손상)
리셋:  제거량 맵 초기화 + 목표 맵 재생성(랜덤) + 시작 지점 복귀
```

**스텝 예산 = 규칙 컨트롤러 시간 × 1.5**

실측 baseline (1737샘플, 38구간):
```
구간 1개 주행 : 중앙값 7.6초 (범위 0.8~276초)
차 1대 전체   : 933초 = 15.6분 (로봇 3대 병렬이면 실제 ~5분)
→ 예산: 구간당 7.6 × 3패스 × 1.5 ≈ 34초
```

**왜 절대 시간 페널티를 정하지 않는가:**
w5 값을 찍는 건 근거가 없다. 대신 예산 방식이면 **"규칙보다 1.5배 시간 안에 더 균일하게"**라는
명확하고 발표 가능한 기준이 된다. 그래도 w5가 필요하면 절차로 정할 것:
```
1) w5 = 0 학습 → 품질 최고, 소요 시간 측정
2) w5 올려가며 재학습 → 시간이 예산 내로 들어올 때까지
3) 품질-시간 Pareto 곡선의 무릎 지점 선택
```
(w5 = 0이면 정책은 "아주 살살 100번 돌기"를 배운다 — 안전·정확하지만 실용성 0)

### 7-7. 개선 여지 baseline — RL이 넘어야 할 선

목표를 중앙값(828)으로 두고 규칙 컨트롤러가 **1회 주행**했을 때:
```
미달 지점     50%    → 절반이 목표 미달
과연마(2배↑)  34%    → 되돌릴 수 없는 손상
제거량 분포   p5=117(목표의 14%) ~ p95=2714(목표의 328%)
```
**같은 목표인데 실제로는 14%~328%로 흩어진다.** 이것이 정량 비교 기준.

### 7-8. ⚠ 미해결 — 접촉 모델 (별도 결정 필요)

BC는 이 분포에서 학습했다:
```
접촉력  0.27 ~ 6.92 N (평균 3.12)
압력    59 ~ 1526 Pa (평균 688)
```
우리 시뮬은 **가상 스프링** 모델이다 (강체 충돌 OFF, 패드 침투 깊이로 힘 계산).
Isaac Lab에서 강체 접촉을 쓰면 완전히 다른 스케일(예: 50N)이 나오고, **BC는 그런 입력을
본 적이 없어 무의미한 값을 뱉는다.**

| 갈래 | 내용 | 비용 |
|---|---|---|
| A. 맞춘다 | 가상 스프링 방식을 새 환경에 이식 | 이식 작업, BC 그대로 사용 |
| B. 안 맞춘다 | 새 환경에서 규칙 컨트롤러 돌려 로그 뽑고 **BC 재학습** | 반나절. 파이프라인 그대로 재사용 |

**권장: B.** 우리가 만든 자산은 특정 가중치가 아니라 **방법론과 도구**
(`extract_dataset.py` → `train.py` → `evaluate.py`, 라벨 실측화, 스무딩, 그룹 분할, 누수 방지).
억지로 맞추다 어중간해지는 것보다 새 환경에서 깨끗하게 다시 만드는 게 낫다.

### 7-9. 착수 전 30분 체크 — BC 전이 가능한가

**RL을 며칠 돌린 뒤에 "BC가 쓸모없었다"를 알면 낭비다.** 학습 시작 전에 반드시:

- [ ] 새 환경에서 규칙 컨트롤러로 몇 구간 주행 → 접촉력 분포 수집
- [ ] 우리 분포(0.27~6.92N, 평균 3.12N)와 비교. 자릿수가 다르면 → **7-8의 B안으로 전환**
- [ ] BC를 그냥 추론시켜 출력이 물리적으로 말이 되는지 확인 (음수/발산 없음)
- [ ] `curvature` 계산 방식 일치 확인 — 우리는 점군 KDTree PCA(λ_min/Σλ).
      메시 기반이면 값이 달라져 BC 입력 분포가 어긋난다
- [ ] **병렬화 주의**: KDTree 쿼리를 2048개 env × 매 스텝 돌릴 수 없다.
      법선·곡률은 **사전 계산해 텐서로 보유**할 것

### 7-10. 남은 결정 사항

- [ ] **차 1대 허용 시간** — 현재 규칙이 3대 병렬로 약 5분. 산업 기준이 있으면 반영,
      없으면 "규칙 × 1.5" 기본값 사용
- [ ] 접촉 모델 A/B (7-8)
- [ ] 목표 제거량 절대값 — 현 데이터 중앙값 828(임의 단위)을 기준선으로 권장
- [ ] `w1~w6` 초기 가중치 — 각 항이 운영점에서 비슷한 크기를 갖도록 정규화 후 튜닝
